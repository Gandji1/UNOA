# Lot 007 — Structures académiques et catalogue des formations

Relecture du 20 novembre 2026 : sections 1 à 5, 16 à 24 et 26 (ORG, CAT, CMS)
des TdR, annexes contrats de données, matrice des accès, cartographie des écrans,
paramétrage régional, ADR 0001 à 0004 et code des lots 001 à 006.

## Problème et résultat attendu

L'université configurée crée elle-même ses composantes (facultés, écoles,
instituts, départements, laboratoires…), puis ses domaines, filières, mentions,
spécialités et parcours, ses programmes, leurs maquettes versionnées, leurs UE
et cours. Rien de tout cela n'est écrit dans le code : la plateforme livre les
moteurs, les éditeurs, les contrôles et les écrans publics qui n'affichent que
ce qui a été publié.

## Exigences

| Module | Exigences | Couverture du lot |
|---|---|---|
| ORG | REQ-ORG-001 à 011 | Unités typées, hiérarchie déclarée, cycle proposé → actif → clos, postes, nominations titulaires/suppléants/intérims datées, vacance, affectations multiples, capacités, demandes de fermeture/fusion/transfert approuvées par un tiers, filiation historique, organigramme public filtré |
| CAT | REQ-CAT-001 à 017 | Taxonomie libre de domaines/filières/spécialités, natures de programme définies par l'administration, programmes et traductions, versions, périodes, UE, cours mutualisés, crédits/coefficients/volumes, options, prérequis sans cycle, compétences, stages/mémoires/soutenances requis, langues/capacités/territoires, contrôle de cohérence, revue, publication immuable, nouvelle version, équivalences, simulation de plan d'études, statut réglementaire vérifié avant ouverture des candidatures |
| CMS | REQ-CMS-002, 003 (partiel) | Fiches programmes publiques versionnées avec statut officiel, recherche filtrée par nature, langue et territoire. Le CMS éditorial reste ouvert. |

Les tarifs (REQ-CAT-012, volet prix) dépendent du module FIN : la version ne
porte pas de prix codé et le point reste ouvert dans la matrice.

## Dépendances

Amont : portées et hiérarchie déclarée (lot 005), droits par portée et audit
(lots 002-003). Aval : admissions (ADM) consomment `admission_open` et le
contrôle réglementaire, scolarité (SIS) référence la version publiée, LMS
rattache les cours du catalogue à leurs versions pédagogiques.

## Modèle (migrations 0006 et 0007)

- Nature de portée `academic_unit` : une composante est une portée, donc les
  droits, l'héritage de configuration et les fenêtres de présence s'appliquent
  sans duplication. Profil `org_unit` : code, statut, visibilité publique.
- `org_position`, `org_appointment` (titulaire, suppléant, intérim ; périodes
  sans rétroactivité ; pas de double nomination ni de dépassement du nombre de
  titulaires), `org_capacity`, `org_change` (fermeture, fusion, transfert) et
  `org_succession`.
- `field_type`, `field_type_parent`, `academic_field` ; `program_kind`,
  `program`, `program_label`, `program_version`, `program_period`,
  `option_group`, `teaching_unit`, `unit_volume`, `course`, `unit_course`,
  `unit_prerequisite`, `competency`, `version_competency`, `unit_competency`,
  `version_requirement`, `version_territory`, `unit_equivalence`,
  `program_authorization`.
- Déclencheurs PostgreSQL : version publiée immuable avec tout son contenu,
  prérequis sans cycle et dans la même version, période antérieure, un seul
  brouillon par programme, revue et vérification par un autre compte,
  ouverture des candidatures seulement sur version publiée et autorisation
  vérifiée en cours de validité.

## Droits

`org.read`, `org.write`, `org.approve` ; `catalog.read`, `catalog.write`,
`catalog.review`, `catalog.publish`, `catalog.authorize`. Toute écriture est
vérifiée par `unoa.has_scope_permission` sur la portée propriétaire ; chaque
refus et chaque acte vont au journal d'audit inaltérable.

## Écrans et API

- `/administration/structures` et `/api/v1/org/...`
- `/administration/catalogue` et `/api/v1/catalog/...`
- Public : `/structures`, `/formations`, `/formations/{id}`, via des fonctions
  `SECURITY DEFINER` qui ne renvoient que des données publiées.

## Tests

Recette HTTP sur PostgreSQL et OIDC de recette, depuis une base académique
vide : deux établissements fictifs Alpha et Bêta aux structures et règles
différentes (semestres contre modules, unités de crédit différentes) ; refus
transverses audités ; doublon de nomination ; nomination rétroactive ; fermeture
d'une unité ayant des filles ; approbation par le demandeur ; UE sans crédit ;
total incohérent ; cycle de prérequis ; auto-approbation ; modification d'une
version publiée ; ouverture sans autorisation ou avec autorisation non vérifiée,
suspendue ou expirée ; simulation avec options manquantes ; page publique vide
sur base vierge. Tests unitaires du moteur de maquette (`packages/domain`).

## Rollback

Migrations additives uniquement. Retour arrière applicatif : redéployer la
version précédente du site ; les tables restent inutilisées. Aucune suppression
physique de contenu publié n'est exposée.
