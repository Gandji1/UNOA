# Lot 011 — Administration des accès (IAM, phase P1)

Relecture du 20 novembre 2026 : TDR §1–3, §16–24, module IAM ; MATRICE_ACCES §1–3 ; CARTOGRAPHIE
« Administration `/admin` » et IAM ; PLAN §1 (« base vierge + contenu créé par l'admin »).

## Problème

Aucun administrateur ne pouvait être créé ni aucun rôle attribué sans SQL : le logiciel n'était pas
administrable depuis une base vierge. Ce lot ferme l'écart de la phase P1 avant de poursuivre P2.

## Exigences

REQ-IAM-001 (compte unique, profils), 005 (sessions, révocation), 006 (rôles composables), 007 (portée,
période), 008 (délégations), 009 (isolation), 010 (contrôle en base), 011 (refus tracés), 014 (invitations).

## Modèle (migration 0011)

Profil de compte (nom, courriel, origine), catalogue de permissions, rôles libellés et archivables,
attributions justifiées et immuables, délégations, invitations, `site.open_registration`, fonctions
contrôlées (`compose_role`, `grant_role`, `revoke_grant`, `delegate_grant`, `invite_account`,
`set_account_state`, `revoke_account_sessions`, `iam_accounts`, `audit_trail`…) et `bootstrap_platform`.

## Écrans et API

`/administration` (vue d'ensemble des studios selon les droits), `/administration/acces` (portées,
comptes, recherche, invitations, rôles et permissions, attribution, retrait, désactivation, sessions,
journal d'audit), `/invitation/{jeton}`, `/espace` (profil, rôles, délégation, sessions), réglage
« création de compte » dans `/administration/site`. API `/api/v1/iam/*`.

## Tests

`administration.fixture.mjs` : amorçage unique, composition, permission inconnue, rôle réservé,
invitation à usage unique, escalade refusée (rôle d'amorçage, permission non détenue, hors portée,
auto-attribution), immuabilité des attributions, délégation bornée et révoquée en cascade,
désactivation et réactivation, fermeture de ses sessions, inscription fermée puis ouverte par site,
journal d'audit réservé.
