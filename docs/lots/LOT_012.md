# Lot 012 — File durable, worker et notifications multicanal

Relecture du 20 novembre 2026 : TDR §15 (worker, outbox, idempotence), §16 (API), §17 (modèles sans
injection), module NOT, CORE-006/010, IAM-013, ADM-013 ; CARTOGRAPHIE NOT ; MATRICE_ACCES.

## Exigences

REQ-CORE-006, REQ-CORE-010, REQ-NOT-002 à 010, REQ-IAM-013, REQ-ADM-013. Dépendances : IAM (comptes,
portées), CMS (langue du site), ADM et LIVE (événements émis).

## Modèle (migration 0012)

- `notification_event` : catalogue des événements émis par le code (variables autorisées, sensibilité,
  envoi externe permis). Technique, non académique.
- `notification_template` : modèle par portée, événement, canal (interne, courriel, SMS) et langue ;
  versions brouillon → publiée (par une autre personne) → retirée ; variables `{{nom}}` limitées au
  catalogue, texte brut uniquement. Héritage : le modèle publié de la portée la plus proche s'applique,
  sinon le texte par défaut du logiciel (fr, en).
- Compte : langue préférée, téléphone ; `contact_consent` (historique non modifiable par canal) ;
  `notification_preference` (événement × canal).
- `job` : file durable (outbox transactionnelle) avec clé d'idempotence, tentatives, report exponentiel,
  verrou à expiration, état `dead` après le plafond, rejeu par une personne habilitée.
- `delivery_attempt` : preuve technique de livraison (canal, adaptateur, destinataire masqué, statut,
  référence fournisseur, erreur assainie) ; `sandbox_message` : boîte de recette de l'adaptateur sandbox.

## Traitement

Événement métier → notification interne rendue dans la transaction → pour chaque canal externe consenti
et activé : tâche `deliver` insérée dans la même transaction → worker (`apps/worker` en continu, ou
`/api/v1/jobs/run` appelé par une tâche planifiée protégée par jeton) → adaptateur `sandbox` ou `http`
(production, secrets en variables d'environnement) → tentative journalisée. Événement sensible : le
message externe ne contient qu'un avis générique et le lien (aucune donnée de décision).

## Droits

`not.read`, `not.manage` (modèles), `not.publish`, `ops.jobs` (files, rejeu, boîte sandbox).

## Écrans

`/administration/notifications` (événements, modèles, aperçu, publication, journal des envois, files et
rejeu, boîte sandbox) ; `/espace` (langue, téléphone, consentements, préférences, export JSON).

## Tests

par un tiers, langue du destinataire, préférence désactivée, consentement absent, événement sensible sans
fuite, envoi sandbox, échec puis relance, file morte et rejeu, idempotence, droits et isolation, export.
Unitaires : rendu et validation des modèles.
