# Lot 027 — Entreprises partenaires et stages

Relecture du 28 novembre 2026 : TDR §8 (Campus-Entreprise : vérification d’entreprise, membres, conventions, maîtres de stage, journaux, rapports, grilles, stage crédité si le programme le prévoit ; « une entreprise ne voit que les candidatures et informations pour lesquelles existe une base légale ») ; modules ENT (REQ-ENT-001 à 011) et STG (REQ-STG-001 à 012) ; dépendances : lots 013/014 (inscriptions pédagogiques), 020 (notes : la note de stage entre comme note provisoire), 012 (notifications), ADR-0016 (cascade).

## Fiche

- **Entités** : `company` (profil public / informations privées séparés, antennes par `parent_id`), `company_document` (pièces justificatives, purgeables), `company_verification` (historique des contrôles : existence légale, mandataire), `company_member` (propriétaire, recruteurs, maîtres de stage), `company_activity` (trace des recruteurs), `company_report` (signalements), `partnership` (convention entreprise–établissement signée des deux côtés) ; `internship_template` (modèle de convention avec référence juridique, approuvé par une autre personne), `internship_grid` (grille pondérée), `internship`, `internship_supervisor`, `internship_signature`, `internship_log`, `internship_message`, `internship_report`, `internship_review`, `internship_event`.
- **Droits** : `ent.read`, `ent.verify` (sensible), `ent.manage` ; `stg.read`, `stg.manage`, `stg.sign`, `stg.validate`. Nouveau modèle de rôle « Responsable des stages et de l’insertion » (établissement, faculté). Les membres d’une entreprise n’agissent que sur leur entreprise et ses stages, sans accès au dossier étudiant.
- **États** : entreprise `pending → approved | rejected`, `approved ↔ suspended`, `→ closed` ; stage `requested → approved | rejected → signing → active → report → evaluated → validated`, plus `broken`, `cancelled` ; événements prolongation, report, litige, absence, maître de stage absent.
- **Règles** : vérificateur ≠ déclarant ; approbation seulement si existence légale et mandat contrôlés avec au moins une pièce ; motif obligatoire pour refus et suspension ; modèle de convention utilisable seulement s’il est approuvé par une autre personne que son auteur et porte une référence juridique ; convention générée et scellée (empreinte) avant signature ; trois signatures (étudiant, entreprise, établissement) sur la même empreinte ; journal et évaluation entreprise impossibles sans maître de stage en fonction ; crédits et note seulement après validation académique, rapport déposé et deux évaluations ; rapport confidentiel visible des seules parties ; clôture d’entreprise : membres retirés, pièces purgées, historique conservé.
- **Écrans** : `/entreprises` (annuaire public), `/entreprises/inscription`, `/entreprise` (espace entreprise : profil, pièces, membres, conventions, stages, tableau de bord), `/stages` (étudiant, maître de stage, encadreur), `/administration/entreprises`, `/administration/stages` (modèles, grilles, décisions, conventions, validation, statistiques par région).
- **Tests positifs et négatifs** (`test/fixtures/internships.fixture.mjs`) : entreprise fictive refusée, auto-validation refusée, approbation sans pièces refusée, suspension motivée, recruteur ajouté puis retiré (droits perdus), visibilité limitée, convention entreprise–université, modèle non approuvé refusé, demande d’un non-étudiant refusée, signature sur empreinte, maître de stage absent bloquant, rupture, prolongation, rapport confidentiel, grille, validation et note provisoire, statistiques par région, clôture et purge.
- **Risques** : données personnelles étudiantes exposées aux entreprises (requêtes filtrées par relation) ; conventions juridiques (référence et approbation humaine, pas de modèle fourni par le code) ; KYB automatisé indisponible — contrôle documentaire humain, registre officiel `BLOCKED_EXTERNAL`.
